Algoritmo A*

Do conceito à prática

O A* é um dos algoritmos mais importantes da Ciência da Computação para encontrar o caminho mínimo em grafos e mapas. Ele une a garantia de otimalidade da busca de custo uniforme (Dijkstra) com a velocidade direcionada de uma função heurística.

f(n) = g(n) + h(n) (custo total estimado = custo real percorrido + estimativa até o destino)
Lucas Marcel • Glauco Paiva • Filipe Campos
Fundamentos

01Visão geral e motivação

O algoritmo A* resolve o problema do caminho mínimo entre dois pontos: dado um grafo com custos não negativos nas arestas, uma origem A e um destino B, encontrar a rota de menor custo total de A até B.

Para entender por que o A* é tão eficiente, vale compará-lo com seus dois "pais" conceituais — sem fórmulas ainda, olhando apenas para o critério que cada algoritmo usa ao escolher o próximo nó:

Intuição central O Dijkstra olha apenas para o passado ("quanto já gastei até aqui?"). A busca gulosa olha apenas para o futuro ("quanto parece faltar até o destino?"). O A* equilibra passado e futuro a cada passo.

02Equação fundamental

f(n) = g(n) + h(n)

g(n) — custo real

Soma exata dos pesos das arestas no melhor caminho conhecido da origem A até o nó n.

Na origem, g(A) = 0. Sempre que encontramos um atalho até n, atualizamos g(n) para o menor valor.

h(n) — heurística

É uma estimativa do menor custo restante do nó n até o destino B.

Não precisa conhecer obstáculos — costuma usar uma distância simples até o destino. No próprio destino, obrigatoriamente h(B) = 0.

f(n) — custo total estimado

Estima o custo completo de ir de A até B passando por n.

Define a prioridade da busca: a cada passo, o algoritmo escolhe explorar o nó candidato com menor f(n).

Exemplo rápido Se já percorremos g(X) = 4 para chegar ao nó X e estimamos que faltam h(X) = 6 até o destino B, então f(X) = 10. Se outro nó Y tiver f(Y) = 8, o A* explora Y primeiro.

Repare nos dois casos extremos que conectam a equação à seção anterior:

  • Se h(n) = 0 para todo nó, então f(n) = g(n): o A* vira exatamente o algoritmo de Dijkstra.
  • Se ignorarmos g(n) e usarmos apenas f(n) = h(n), obtemos a busca gulosa — rápida, mas sem garantia de menor caminho.

03Como o algoritmo funciona

Para executar a equação f(n) = g(n) + h(n) em um grafo, o A* precisa manter apenas três controles simples durante a busca:

1. Fronteira (open set)

Lista dos nós já descobertos que ainda aguardam exploração. Sempre retiramos dela o nó com menor f(n).

Desempate: em empate de f, prefere-se o menor h(n) (mais perto do destino).

2. Explorados (closed set)

Conjunto dos nós cujos vizinhos já foram todos avaliados, evitando retrabalho desnecessário.

3. Melhor custo e rota

Para cada nó, guardamos o menor custo real g encontrado até agora e o seu predecessor (de qual nó viemos) para reconstruir o caminho ao final.

Passo a passo da busca

  1. Início: coloque a origem A na fronteira com g(A) = 0 e f(A) = h(A).
  2. Escolha: retire da fronteira o nó atual com o menor valor de f.
  3. Teste de parada: se atual == B, pare e reconstrua o caminho seguindo os predecessores de volta até A.
  4. Relaxamento dos vizinhos: para cada vizinho acessível de atual, calcule o custo passando por atual. Se for menor que o melhor g conhecido daquele vizinho, atualize seu g, recalcule f, salve atual como predecessor e coloque-o na fronteira.
  5. Repetição: marque atual como explorado e volte ao passo 2. Se a fronteira esvaziar sem alcançar B, não existe caminho.
Armadilha clássica: quando parar o A*? Nunca pare quando o destino B for descoberto pela primeira vez como vizinho! Pode existir outro nó na fronteira que leve a B com custo menor. O algoritmo só garante otimalidade quando B é retirado do topo da fronteira, pois nesse momento f(B) = g(B) é menor ou igual ao f(n) de qualquer outro candidato restante.

04Admissibilidade

A pergunta central do A* é: qualquer função h(n) garante encontrar o caminho mínimo? Não. A heurística pode subestimar o custo restante, mas nunca pode superestimar.

0 ≤ h(n) ≤ h*(n)
∀ n ∈ V

Aqui, h*(n) representa o menor custo real de n até o destino B. Quando h(n) ≤ h*(n) para todo nó, dizemos que h é admissível (otimista) — e o A* garante encontrar o caminho ótimo se existir algum.

O que acontece se h(n) superestimar?

O caminho ótimo A → C → B custa 5, mas como h(C) = 10 superestima o real h*(C) = 3, o A* vê f(C) = 12 e encerra na rota pior A → D → B (custo 9).

Por que a admissibilidade garante o ótimo?

  1. Suponha que exista um caminho ótimo de custo C*, mas o A* estivesse prestes a retirar B com um caminho pior g(B) > C*.
  2. Como o caminho ótimo ainda não foi concluído, há algum nó n dele aguardando na fronteira com seu custo real ótimo g*(n).
  3. Sendo h admissível, o valor estimado de n é obrigatoriamente menor que o de B:
f(n) = g*(n) + h(n) ≤ g*(n) + h*(n) = C* < g(B) = f(B)

Como a fronteira sempre retira o menor f primeiro, n sairia antes de B — contradição! Logo, ao expandir B, seu custo só pode ser C*.

Dominância: qual heurística admissível é melhor? Entre duas heurísticas admissíveis h₁ ≤ h₂ ≤ h*, dizemos que h₂ domina h₁: por ser mais próxima do custo real sem ultrapassá-lo, h₂ expande menos nós. No extremo inferior, h = 0 (Dijkstra) é admissível, porém a mais fraca.

05Consistência

Mesmo sendo admissível, uma heurística pode causar oscilações nas estimativas e obrigar o algoritmo a revisitar nós já explorados. Para evitar isso, exigimos uma propriedade um pouco mais forte: a consistência (ou monotonicidade).

h(n) ≤ custo(n, n') + h(n')
h(B) = 0

Desigualdade triangular: a estimativa direta h(n) não pode ser maior do que dar um passo real até o vizinho n' e somar a estimativa a partir dele.

Relação com admissibilidade

Toda heurística consistente é automaticamente admissível (a recíproca nem sempre vale).

Na prática, quase todas as heurísticas geométricas usadas em mapas e grades satisfazem as duas propriedades.

Ganho prático na execução

Com consistência, os valores de f(n) nunca diminuem ao longo de um caminho.

Por isso, na primeira vez que um nó sai da fronteira seu g(n) já é definitivo — não é preciso reabrir nós do closed set.

06Funções heurísticas

Em grades e mapas 2D, não precisamos criar estimativas manualmente: usamos distâncias geométricas entre as coordenadas do nó atual e do destino, que são naturalmente admissíveis e consistentes.

Heurística Fórmula (dx = |x₁ - x₂|, dy = |y₁ - y₂|) Movimento indicado Observação
Manhattan (L₁) c_min · (dx + dy)
4 direções N, S, L, O
Exata quando não há obstáculos nem arestas com pesos diferentes.
Euclidiana (L₂) c_min · √(dx² + dy²)
Qualquer ângulo 4 ou 8 direções (diag. ≥ √2)
Admissível em 4 e 8 direções, mas subestima mais em grades 4-dir (expande mais nós).
Chebyshev (L∞) c_min · max(dx, dy)
8 direções Diagonal = 1
Considera o passo diagonal com mesmo custo do passo ortogonal.
Octile c_min · (max(dx,dy) + (√2 - 1)·min(dx,dy))
8 direções Diagonal = √2
Modelo realista de grades onde andar na diagonal custa √2 ≈ 1.414.
Cuidado com os pesos! Para que uma distância geométrica seja admissível, multiplique-a pelo menor custo possível de aresta c_min. Quando o menor peso do grafo é 1 e os demais são maiores ou iguais a 1, a distância de Manhattan pura continua admissível. Já se existir alguma aresta mais barata (como custo 0.5), é preciso aplicar o fator c_min = 0.5 para não superestimar o custo real.

07Complexidade e variações

Tempo: pior caso vs prática

No pior caso (quando h não ajuda), o A* visita quase todo o grafo como o Dijkstra: O((|V| + |E|) log |V|).

Na prática, com uma boa heurística, apenas uma pequena fração dos nós chega a ser expandida.

Espaço: o verdadeiro gargalo

O(|V|) na memória, pois o A* guarda todos os nós gerados na fronteira e nos registros de rota.

Em grafos enormes (como mapas continentais ou quebra-cabeças), o A* costuma esgotar a memória RAM antes do tempo de CPU.

Variações para cenários reais

Cenário / problema Variação Como resolve
Precisa de mais velocidade (aceita margem de erro) A* ponderado Usa f = g + w · h (w > 1): explora menos nós garantindo custo ≤ w · C*.
Faltou memória RAM IDA* Substitui a fronteira por busca em profundidade limitada por f, reduzindo espaço para O(d).
Área de busca muito ampla A* bidirecional Dispara duas buscas simultâneas (A → B e B → A) até se encontrarem no meio.
Grade grande com áreas abertas Jump Point Search (JPS) Pula células simétricas em linha reta sem colocá-las na fronteira.
Grafo gigante em hardware multicore A* paralelo Distribui a expansão de nós ou o cálculo de vizinhos entre várias threads.

08Pseudocódigo

Juntando tudo o que vimos nas seções anteriores, o algoritmo A* completo se resume em três blocos diretos: 

função A_Estrela(grafo, origem, destino, h):
    // 1. Preparação
    fronteira ← fila de prioridade ordenada por menor f
    custo_g   ← mapa com valor padrão +∞
    veio_de   ← mapa vazio

    custo_g[origem] ← 0
    fronteira.inserir(origem, f = h(origem, destino))

    // 2. Seleção e teste de parada
    enquanto fronteira não estiver vazia:
        atual ← fronteira.retirar_menor_f()

        se atual == destino:
            retornar reconstruir_caminho(veio_de, origem, destino), custo_g[destino]

        // 3. Relaxamento dos vizinhos
        para cada vizinho em grafo.vizinhos_acessiveis(atual):
            novo_g ← custo_g[atual] + grafo.custo(atual, vizinho)

            se novo_g < custo_g[vizinho]:
                veio_de[vizinho] ← atual
                custo_g[vizinho] ← novo_g
                novo_f           ← novo_g + h(vizinho, destino)
                fronteira.inserir_ou_atualizar(vizinho, f = novo_f)

    retornar SEM_CAMINHO
Detalhes práticos de implementação
  • Min-Heap (heap binário): estrutura padrão para implementar a fronteira e retirar o menor f em O(log |V|).
  • Lazy deletion: como heaps binários simples não atualizam prioridades no meio da árvore, costuma-se inserir a nova cópia com novo_g menor e ignorar entradas antigas ao retirá-las da fila (se g_retirado > custo_g[atual]: continuar).
